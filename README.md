# F1 Drivers' Championship — auto-updating standings chart

A self-contained, static chart of cumulative F1 World Drivers' Championship
points by race (2025 vs 2026), hosted free on GitHub Pages. A scheduled GitHub
Action re-fetches live standings weekly, regenerates `data.json`, and commits it
if it changed — which auto-redeploys the site. No backend, no server, no
database.

```
├── index.html                       # chart shell (self-contained SVG, no CDN)
├── data.json                        # generated data — committed to the repo
├── scripts/
│   └── update_standings.py          # fetches the API, writes data.json
├── .github/workflows/
│   └── update-standings.yml         # scheduled + manual job
├── requirements.txt
└── README.md
```

## How it works

- **`index.html`** builds both charts at runtime as pure SVG (no charting
  library / CDN — this is deliberate, so the page also works when opened locally
  via `file://`). It `fetch()`es `./data.json` on load and renders once it
  resolves. If the fetch fails it shows a small inline error in each chart box.
- **`data.json`** holds the top-6 drivers by points (as of the latest completed
  round) for each season, their cumulative points per round, plus metadata for
  the labels/footer. It is regenerated by the update script and committed to the
  repo — GitHub Pages serves it as a static file.
- **`scripts/update_standings.py`** pulls from the free, no-auth
  [Jolpica F1 API](https://api.jolpi.ca/ergast/f1/) (the Ergast-compatible
  successor to the retired Ergast API):
  - `/{season}/races.json` — race calendar; only rounds whose date is on or
    before today (UTC) are treated as completed.
  - `/{season}/{round}/driverstandings.json` — cumulative standings after that
    round. The `points` field is the official post-round total (race + sprint
    already combined), so nothing extra is added.
  - The **top-6 set is recomputed from live data every run** (never hardcoded),
    because the 2026 leaderboard shifts through the season.
  - On any HTTP error or unexpected response shape the script exits non-zero and
    does **not** write a partial `data.json`.

## Enable GitHub Pages

1. Push this repo to GitHub.
2. **Settings → Pages → Build and deployment → Source: "Deploy from a branch".**
3. Select the `main` branch and the `/ (root)` folder, then **Save**.
4. The site publishes at `https://<your-username>.github.io/<repo-name>/`.

Every time the Action commits an updated `data.json` to `main`, Pages
redeploys automatically.

## The scheduled update

`.github/workflows/update-standings.yml` runs:

- **On a schedule:** every Monday at 12:00 UTC (`cron: "0 12 * * 1"`). Jolpica's
  maintainers aim to publish one data update per race weekend on the Monday
  after the event, so a Monday-noon run lines up with when fresh results land.
  Adjust the cron if you want more buffer.
- **On demand:** via `workflow_dispatch`.

Steps: checkout → set up Python → `pip install -r requirements.txt` → run the
update script → commit `data.json` **only if it changed** (via
[`stefanzweifel/git-auto-commit-action`](https://github.com/stefanzweifel/git-auto-commit-action)).
The job has `contents: write` permission so it can push. If the script fails
(API error, unexpected data), the job fails visibly in the **Actions** tab and
nothing is committed — no bad data.

### Trigger it manually

**Actions** tab → **Update F1 standings** → **Run workflow**. Useful for testing
or forcing a refresh right after a race.

## Run the update script locally

```bash
pip install -r requirements.txt
python scripts/update_standings.py
```

This rewrites `data.json` in place. To preview the chart locally you need to
serve the folder over HTTP (the `fetch('./data.json')` call does not work over
`file://`):

```bash
python3 -m http.server 8000
```

Then open <http://localhost:8000/index.html>.

## Sanity check

The 2025 season is complete and immutable — the script's output for it should
match:

| Driver | 2025 final points |
|---|---|
| Lando Norris | 423 |
| Max Verstappen | 421 |
| Oscar Piastri | 410 |
| George Russell | 319 |
| Charles Leclerc | 242 |
| Lewis Hamilton | 156 |

If the 2025 numbers don't match, something in the round-fetching/aggregation is
wrong — debug that before trusting the in-progress 2026 figures.
